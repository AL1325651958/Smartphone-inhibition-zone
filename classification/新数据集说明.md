## 划分：批次不交叉 + 稀疏类分层

两个约束在打架，我同时满足了：

1. **同一个采集批次的图不能跨划分**（否则同皿泄漏，就是之前 100% 那个坑）
2. **稀疏类要出现在 train/val/test 三边**（E 只出现在 8 个批次，DA 只有 11 个）

第一次用贪心分配时，**E 全部 8 张都落进了 train，val 和 test 一张 E 都没有** —— 这样
E 类在验证/测试上完全无法评估。所以改成 `StratifiedGroupKFold`，以批次为 group、
以**该批次最稀有的类**为分层标签，才把 E 和 DA 摊到三边。

最终验证：

- 批次总数 **27**，跨划分的批次 **0** ✅
- 空的 (split, class) 单元格：**无** ✅
- 每个划分的批次数：train 17 / val 5 / test 5

## 仍需注意

**E 类依然是最短板**：全数据集只有 8 张，val 和 test 各只有 1 张。这意味着
E 的性能估计会非常不稳定（1 张图对错就是 0% 或 100%）。建议继续补标 E，
或者最终论文里对 E 单独说明样本量。

DA（11 张）、其余类（23–27 张）相对够用。

## 复现

```powershell
$env:PYTHONPATH="..\_tools\pylibs"

# 1. 从 Label Studio 抓全部标注（需服务在跑）
python labelstudio\_write_token.py    # 生成 token（在 venv 里跑）
python fetch_annotations_api.py       # 下载 156 个 task
python resolve_annotations.py         # 解析出 144 个带标签的

# 2. 构建数据集
python build_dataset_expanded.py
python verify_expanded.py
```

> 说明：`_write_token.py` 需要用 Label Studio 自带的 Python 执行：
> `_tools\ls-venv\Scripts\python.exe`，且需设置 `DJANGO_DB_NAME` 环境变量。
> 见 `fetch_annotations_api.py` 顶部注释或直接复用已生成的
> `labelstudio/_token.txt`（有有效期）。
