================================================================
  抑菌圈分析 App —— 模型技术文档（自研模型版）
  best.onnx（分割） · class.onnx（分类）
  输入 · 输出 · 预处理 · 后处理 · 核验结果
================================================================

App 不使用 YOLO：两个模型都由本仓库的 Python 项目训练并导出为 ONNX，
配套的 C# 封装为 `ZoneSegModel.cs`（分割）与 `PillClassifier.cs`（分类）。

旧模型备份：`Antibacterial zone/_original_onnx/`
  · best.onnx / class.onnx —— 首投稿用的 YOLOv8n-seg 与 YOLOv8s-cls（仅存档，接口不兼容）
  · class_pillcnn160.onnx  —— 中间版本（PillCNN@160，论文里的消融基线，非最终部署模型）


================================================================
1  分割模型 best.onnx
================================================================

1.1  来源
----------------------------------------------------------------
  训练代码    Antibacterial zone mask/semseg/（原生 PyTorch）
  架构        ResNet18 编码器 + U-Net 解码器，2 通道分割头（14.4 M 参数）
  权重        Antibacterial zone mask/runs_semseg/20260918_051406_resnet18/best.pt
              sha256 aafd545c4f70f8005c1da2c53e408793e32de55774765101a39946f33f823676
  导出脚本    Antibacterial zone mask/semseg/export_onnx.py
  训练数据    78 张培养皿照片 / 31 块物理平板（按平板整体划分，防泄露）
              划分：train 38 张(13 块) + 增强 570 → 608；val 20 张；test 20 张(13 块)


1.2  输入
----------------------------------------------------------------
  名称/形状   input : float32 [1, 3, 640, 640]
  颜色顺序    RGB
  数值范围    0 .. 255      ← ImageNet 归一化已烘焙进计算图
  几何处理    原图**整图双线性 resize** 到 640×640：
              · 不做 letterbox、不补灰边
              · 非等比（4032×3024 → 640×640 会拉伸）
  依据        semseg/dataset.py（训练时就是这条路径）


1.3  输出
----------------------------------------------------------------
  名称/形状   probs : float32 [1, 2, 640, 640]
  语义        逐通道 sigmoid 概率（0..1）
              通道 0 = Area   抑菌圈
              通道 1 = Yaoping 药片


1.4  后处理（ZoneSegModel.BuildInstances）
----------------------------------------------------------------
  阈值        0.45（两通道共用，来自 semseg/config.py 的 THRESH）
  最小面积    30 px（640 尺度，来自 semseg/infer.py 的 min_area）

  ① 药片实例
     `diskProb > 0.45` 做 8 连通域 → 每个连通域一个药片实例
     置信度 = 该连通域内 diskProb 的均值

  ② 抑菌圈实例（关键：相邻圈会融合，不能用连通域）
     种子 = 每块药片连通域的质心（四舍五入到整数像素、clamp 到 [0,639]）
            质心不在圈掩膜内时，在半径 32 px 方窗内取最近的圈像素作种子
     搜索空间 = `zoneProb > 0.45` 的像素集合
     多源 BFS（8 邻域）同时从所有种子扩散，每个圈像素归属最早到达它的种子
     每块药片的圈实例 = 归属给它的像素集合；空或 < 30 px → has_zone = false
     与任何种子都不连通的圈像素 → 仅计数（orphan_zone_px），不产生实例

  ③ 坐标还原（各向异性）
     orig_x = mask_x / (640 / W0) = mask_x × W0 / 640
     orig_y = mask_y / (640 / H0)
     面积   = 掩膜像素数 × (W0/640) × (H0/640)
     等效直径 = 2 × sqrt(面积 / π)          ← 用掩膜面积算，不用轮廓 shoelace

  ④ 轮廓（仅用于绘制）
     逐行扫描每个实例的左右边界 → 左边界自上而下 + 右边界自下而上拼成闭合多边形，
     再按 ③ 映射到原图坐标

  ⑤ 测试时增强 TTA
     5 视图：原图、rot90(1/2/3)、水平翻转；输出反变换后逐像素取平均
     ZoneSegModel.UseTta 可关闭（关掉后测试宏平均 Dice 由 0.9409 降到 0.9376）


1.5  实测指标
----------------------------------------------------------------
  语义（官方测试报告 runs_semseg/20260918_051406_resnet18/test_report.md，含 TTA）
    Area    Dice 0.9561  IoU 0.9159  P 0.9597  R 0.9525
    Yaoping Dice 0.9257  IoU 0.8616  P 0.9330  R 0.9185
    宏平均 Dice 0.9409（无 TTA 对照 0.9376）

  App 端（C#，本机 20 张 test 图，与真值标注逐实例对比；见 _verify/compare_seg.py）
    Area    预测 136 / 真值 110，P 0.802  R 0.991  F1 0.886  匹配 IoU 0.757
    Yaoping 预测 141 / 真值 143，P 0.993  R 0.979  F1 0.986  匹配 IoU 0.858
    语义并集 Dice：Area 0.957 / Yaoping 0.924
    Area 的假阳性来自「本来没有抑菌圈的药片也被分到一小块区域」，
    这与标注里 Area 多边形数（454）少于药片数（555）的实际情况一致。

  速度（ONNX Runtime CPU，warmup 后中位数）
    单视图 640×640 约 0.33 s；App 默认开 5 视图 TTA，单张图约 3–5 s（CPU）

2  分类模型 class.onnx
================================================================

2.1  来源
----------------------------------------------------------------
  训练代码    药片CNN/train_disknet.py（模型定义 disknet_model.py）
  架构        DiskNet-small：固定 DoG 高通分支（σ=1.0 / 2.5）+ 两层 stem（224→112）
              + 四段残差（32/64/128/256 @ 112/56/28/14，SE 注意力）
              + SPPF + 多尺度 token 门控头；3,879,467 参数
  权重        药片CNN/runs/disknet224_small/best.pt（14.9 MB）
  导出脚本    药片CNN/export_onnx_disknet.py
              （导出时把 HighPass 的动态核改写为静态 buffer，数值漂移 0.000e+00）
  训练数据    药片CNN/dataset_augmented224（144 张原始裁剪来自 27 个采集批次，
              其中 87 张进训练；离线增广后 train 783 / val 87 / test 28）


2.2  输入
----------------------------------------------------------------
  名称/形状   image : float32 [N, 3, 224, 224]     （N = TTA 视图数，App 用 5）
  颜色        灰度复制成 3 通道（R=G=B）
  数值范围    0 .. 255      ← (x/255 - 0.5) / 0.25 已烘焙进计算图


2.3  输出
----------------------------------------------------------------
  logits : float32 [N, 7]   原始 logits（**未过 softmax**）
  probs  : float32 [N, 7]   softmax 概率（供参考/调试）
  类别顺序   CRO, DA, E, LEV, LZD, P, VA

  App 取 logits：对 5 个 TTA 视图的 logits 求平均后再 softmax —— 与
  药片CNN/ensemble_eval.py 的 predict() 完全一致。


2.4  预处理（PillClassifier.cs，与训练/评估管线对齐）
----------------------------------------------------------------
  ① 灰度化     BT.601：0.299R + 0.587G + 0.114B（+0.5 取整）
  ② 缩放       PIL 风格可分离 BICUBIC 缩放到 224×224
               （向下缩放时滤波支撑按 scale 放大以避免混叠）
  ③ 复制通道   灰度复制为 3 通道，数值 0..255
  ④ TTA 5 视图 原图、水平翻转、垂直翻转、
               −10° 与 +10° 旋转（fill = 128，PIL 语义：正角度 = 逆时针）
  ⑤ logits 平均后 softmax，取 argmax

  **没有 CLAHE / 锐化 / Gamma**：DiskNet 的数据集是原始灰度裁剪。
  实测核验：dataset_augmented224 的图与「原始裁剪 resized」的逐像素差
  只有 0.23–0.54 灰度级，而做 CLAHE(2.0) / CLAHE(3.0) 增强后分别差
  23–50 / 26–56 灰度级 —— 说明数据集确实没有做增强。
  这一条与稿件附加文件 Table S5 的 "Greyscale disk crop replicated to three
  channels" 一致；而旧版 App（PillCNN 时代，数据集是增强过的）确实需要
  CLAHE 链路，那份实现留在 git 历史里。


2.5  精度
----------------------------------------------------------------
  评测划分    batch-disjoint：28 张测试裁剪来自 5 个采集批次，这些批次不参与训练/验证
  单模型      0.857（无 TTA）
  单模型+TTA  **0.929**   ← 本 App 打包的配置
  5 seed 集成 + TTA  0.929，macro-F1 0.927（论文报告的配置；集成主要提升 macro-F1）
  seed 跨度   0.750 – 0.964（均值 0.857，SD 0.081）——28 张测试集，单张即 3.6 个百分点
  对照        把印字模糊掉后准确率降到 0.172，说明模型主要靠读印字

  本机核验（App 真实链路，C# ↔ Python 参考实现）
    · 数据集 224 测试图（28 张）：C# 0.9286 / 参考 0.9286
    · 同一批**原始裁剪**（App 真实输入）：C# 0.9286 / 参考 0.9286
    · top-1 一致率：原始裁剪 28/28；224 图 27/28（唯一分歧是 0.300 vs 0.302 的平票）
    · 同类别置信度平均差 0.0036，最大 0.015

4  已知注意事项
================================================================

  1) EXIF 方向
     SkiaSharp 的 SKBitmap.Decode **不应用 EXIF 方向**，OpenCV/PIL/浏览器会应用。
     本 App 一直在「存储像素方向」上工作：
       · 测量量（等效直径、圆心距、抑菌距离、比值）旋转不变，不受影响
       · 与标注（Label Studio 按 EXIF 正立方向绘制）比较时，需要先把预测掩膜
         旋转同样的角度（_verify/compare_seg.py 已处理）
     若以后要「显示方向与相册一致」，需按 SKCodec.EncodedOrigin 旋转解码结果，
     并注意分类器的训练裁剪图是按当前方向采集的。

  2) 输入必须 0..255
     两个模型的归一化都在图内完成。若误传 0..1 的输入，输出会完全错乱
     （表现为概率全 0 或全 1、类别退化为单一类）。

  3) 各向异性缩放
     分割是「整图拉伸到正方形」，因此很扁/很长的图会有较大的形状畸变。
     本数据集 76/78 张为 4032×3024（4:3），实测正常；若以后拍摄比例差异很大，
     建议重新训练（加 letterbox 或保持原始比例分块推理）。

  4) 体积与速度
     best.onnx 54.9 MB（FP32）+ class.onnx 14.8 MB ≈ 70 MB，会直接进安装包。
     单张药片裁剪的分类耗时 = 5 个 TTA 视图 × DiskNet-small（3.88 M 参数）；
     若端上太慢，可把 TTA 关掉（准确率 0.929 → 0.857）或只保留 3 视图。
     分割如需瘦身，可对 best.onnx 做动态 int8 量化（约降到 14 MB），
     但必须重跑 _verify 核验并确认 Dice 不下降。

  5) 模型文件位置
     运行时可执行文件旁不需要模型；App 通过 MauiAsset 从 Resources/Raw/ 读取。
     替换模型后必须重新构建（bin 目录里会残留旧模型副本）。
